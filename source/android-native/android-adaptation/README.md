# Android 独立回放适配

## 终局与网页比对、随机种子匹配（2026-10-21 hotfix11）

- 网页不含对局随机种子，而骷髅帝王召唤小骷髅等技能会消耗引擎随机数。原先所有对局都用固定种子 1784463263，所以 02CY92YUQPY9 的终局与网页相反（实测：换种子后结局差异很大）。
- 原先只有在技能目标有歧义时才比对网页终局塔血，其他对局从不比对，却显示“整局校验通过”。现在每场准备完都比对。
- 不一致时按源哈希生成固定的 60 个 int32 种子逐个尝试（每个种子单独校准发牌，约 10 秒一个）。中途提前结算或技能无目标的种子直接淘汰。按以下优先级选出最接近网页的一次完整执行：完全一致 → 被摧毁的塔相同 → 胜负相同 → 不符；原种子也参与比较，一旦完全一致立即停止。
- 选中结果写入状态（`page_match`、`page_hp_difference`、`random_seed`、`random_seed_inferred`）和 `seed-search.json`。面板和行状态分别显示：✓ 已就绪 / ✓ 已就绪·终局近似 / ⚠ 已就绪·仅胜负同网页 / ⚠ 已就绪·与网页不符。种子是推断出来的，不代表还原了原局过程。
- 实测 02CY92YUQPY9：60 个种子中 18 个完整执行，0 个完全一致，1 个被摧毁的塔相同（种子 −1350491712，塔血合计差 3484）。游戏内终局与网页相同：对方右塔被摧毁，Mohamed 1:0 获胜。

## 队列提前准备（hotfix10）

- 回放加入队列（悬浮窗/控制台「添加 HTML」或 Edge「加入队列」）后，自动在当前游戏进程里提前完成准备：读取资源、校准发牌、整局预演、核对指令，停在 ready_to_open。每行右侧显示状态：等待准备 / 准备中·… / ✓ 已就绪 / 排队中。点「播放下一个」只剩前台加载，实测约 14 秒开播（原先约 50 秒）。上一场结束、客户端回到大厅后，队列下一场也会自动准备。
- 提前准备绝不发布战斗场景：只有用户点播放时写入的前台信号才会开播，主控制台的旧切换逻辑对提前准备的任务不生效。等待时间对提前准备的请求放宽为 2 小时（`prepare_ahead`），其他请求仍是 10 分钟。
- 自动准备只在游戏已运行、没有任务占用时进行，同一行在同一游戏进程内只自动尝试一次，从不自动重启游戏。
- 运行时规定：已进入原生执行的准备被取消后，必须结束那个游戏进程才能释放。所以「删除已就绪那一行」需要 5 秒内连点两次确认；「立即播放」另一场、「重放上一场」会先在前台安全取消，再仅重启这一游戏进程（核对 pid + 启动时间），之后自动准备，用户请求的那场会自动开播。「置顶」不会打断已就绪的那场，改为排在它后面；改倍速只作用于之后准备的回放，已就绪的行会标出它的倍速。

## 全程在游戏内：Edge 小窗、浏览器桥接直达悬浮窗（2026-10-20 hotfix10）

- 悬浮面板「小窗打开 Edge（RoyaleAPI）」：用你自己的 Edge（保留 Google/RoyaleAPI 登录），以系统自由窗口浮在游戏下半屏，可拖动标题栏、⤢/✕。普通接口无法把已有全屏任务改成小窗，所以用现有 root 运行固定命令 `am start --windowingMode 5 …` 和 `am task resize <id> …`，没有 root 时退回普通打开。
- Edge 脚本的「在安卓控制台播放」不再打开控制台：新的隐藏接收页 `BrowserBridgeActivity` 只解码链接，交给悬浮窗显示“立即播放 / 加入队列 / 忽略”，然后立即回到 Edge/游戏；收到链接本身从不播放。悬浮窗没开时会自动启动；无悬浮窗权限时退回原确认页。
- 从悬浮窗开播一律走服务端前台切换，不需要控制台可见；真正开始步进后面板自动收起。核验终局后在悬浮窗提供「重放本场」「退出回放」（退出后自动重新打开游戏），不再跳回控制台。重放/退出逻辑与主控制台共用 `ConsoleActions.finishReplay`。

## 游戏内悬浮控制台与可编辑队列（2026-10-20 hotfix9）

打开一次控制台后，屏幕边缘出现可拖动的圆形「回放」按钮，在游戏界面上点它展开或收起悬浮控制台；通知栏「回放悬浮控制台」也可展开/收起。面板显示当前状态，可「播放下一个」、切换倍速、停止当前回放（需连点两次确认，仍只重启游戏客户端），并管理待播队列：「添加 HTML」（系统文件选择器，可多选，选完回到原界面）、每场「置顶」「删除」、「清空队列」（连点两次确认）。主控制台的队列下方也有同样的置顶/删除。「关闭悬浮窗」后不再自动出现，可在主控制台「开启游戏内悬浮控制台」恢复。

悬浮窗不获取焦点、只接收自身范围内的触摸，游戏仍是前台活动，面板外的触摸照常交给游戏。播放下一场沿用原队列路径（服务端前台切换、同样的任务归属与场景校验），不覆盖仍持有现场的任务。删除只移除队列里尚未开始的副本（`replay-queue/<id>.html`），不影响正在播放的任务、已保存回放或诊断记录；下一场正在开始时拒绝改动队列。

## 终局返回与进程退出恢复（2026-10-18）

原生终局回执通过校验后，前台服务结束观察并自动返回控制台一次，显示「重放本场」「退出回放」。不是根据网页时长或最后一次下牌猜测结束。观察器退出不卸载游戏仍在使用的原生回调，原始 HTML、执行回执和终局记录继续保留。

「重放本场」读取本任务自己的原始 HTML 并核对 SHA256；先重新检查终局、进程代际、回放 controller 和私有回调归属，仅关闭该游戏进程，再打开客户端、等待空闲大厅，以全新任务重放。「退出回放」执行同样的安全归属检查后只关闭游戏，控制台恢复就绪，不退出模拟器，也不自动重新播放。未知或其他场景拒绝关闭，不能通过删锁绕过。

若用户已经手动结束游戏进程，控制台后台只读检查旧 PID 与启动时间；确认消失或 PID 已复用后记录释放凭据，恢复初始可操作界面。不把 root 拒绝、读取超时或损坏的进程信息当作退出，不关闭替代进程，不改写原终局/错误文件。检查不在界面线程运行。

源码回归、设备状态测试与真实整局测试分别记录在 TESTING.md；构建或状态测试通过不等同于原生回放流程全部通过。

## 外部 Edge 回放桥接（2026-10-18）

新增 [手机浏览器桥接说明](browser-bridge/README.md) 和 `browser-bridge/royale-replay-phone.user.js`。
普通 Edge 中登录 RoyaleAPI 并进入完整 Replay 详情页，脚本按钮仅在用户点击时把本页完整 HTML 经本机 Intent 交给控制台。控制台校验大小、GZIP、UTF-8、SHA256和来源回放编号后，显示本场确认；确认后才调用原有独立播放服务。无上传、Cookie导入、后台采集、网络监听或代理改动。

这需要包含 `BrowserImportActivity` 的新版控制台；旧APK不能接收桥接。仅生成脚本不等于已经在 Edge 安装。浏览器若要求可信点击，需再点脚本显示的打开控制台链接；每次本机确认不能由网页绕过。源事件、全局延后20tick和既有原生验证/场景归属流程均不修改。

## 精简控制台（2026-10-17）

### 最新：悬浮进度卡／前台加载／仅内置浏览器直连

点击播放不再立即打开游戏。准备、校准、整局执行与往返验证期间保持控制台可见；全部通过、来源与本次请求一致、游戏 PID＋启动代际一致后，先显示用户授权的悬浮进度卡，再自动打开游戏一次。游戏回到前台时可能先出现启动页，因此还要等严格的普通空闲大厅连续稳定两秒，才首次提交原生回放。原生提交前仍独立检查大厅，不能覆盖其他对局。

悬浮卡显示加载状态，不接收触摸、键盘或屏幕内容；真正观察到本场原生帧与 tick 推进后才移除，不把排队、整局预演、场景提交或资源加载当成实际播放。失败或取消时移除卡片并保留通知/原始记录，不重复发布原生任务。需要显示在其他应用上层的系统授权，由用户确认；不代为更改全局权限。此方案仍在原生游戏内播放，尚未将游戏画面嵌入控制台。

新版已安装到现有安卓1并完成真实 HTML 全链路复测：154条源事件、原生JSON往返、前台加载、实际开播后悬浮卡自动收起、tick6208（310.4秒）终局。53项主机测试、24项设备状态检查、6项设备解析检查通过；这些检查与实际回放证据分别记录。安装包 SHA256：`d7cac15034d4049e0925359137a5f37b47a538ccd269ddaa338b9b8c549e2a44`。私有验证现场仅存于本机，不随源码分发。

网页按用户后续明确要求改为 **仅本应用 WebView DIRECT**，不再继承固定代理，也不设置全局代理、VPN、DNS、Clash 或电脑网络。无法设置应用内路由时明确停止访问，不偷偷改其他设置。普通权限保留 INTERNET 与 FOREGROUND_SERVICE；另有用户明确批准、由系统管理的 SYSTEM_ALERT_WINDOW 特殊访问。

旧 `needs_review` 仍不能靠删除锁绕过；重启游戏后比较 PID 与启动时间，确认旧进程代际已消失，才允许用户重新导入。终局回执与错误文件保留。控制台内嵌实时游戏画面尚未实现，不能用整屏截图（可能拍到控制台本身）冒充原生播放。

主界面仅保留三个常用入口：**打开 RoyaleAPI 网页、选择 HTML 并播放、播放倍速**。导入真实 HTML 后自动提交同一手机本地播放链，不再需要单独点解析、准备、编译、播放。运行自检、root 检查、电脑配对等调试按钮已从普通界面移除；底层工具和测试仍保留。

有回放记录时显示「返回游戏观看」；仅在观察器仍正常、能够处理安全停止时显示「停止当前回放」。停止需要确认，并重新验证场景归属，不操作其他对局。过期状态不会伪装成仍在运行，也不会把点击停止当成停止成功。

状态置顶，分别显示准备、整局校验、大厅恢复、战场加载、实际播放进度和终局。切到游戏后有悬浮进度卡陪同加载，开播后自动收起；也可以下拉通知栏看本机状态，点通知回控制台，再点「返回游戏观看」。不申请无障碍或录屏权限。播放/终局每两秒更新原生进度；暂停不推进 tick，但心跳仍更新。已有有效原生终局回执、只是后续观察异常的旧任务，会显示「终局已验证、后续观察结束」，不改写原始错误记录。

内置网页使用 AndroidX WebKit 1.9.0，通过本应用的 ProxyController 设置 DIRECT，仅影响本应用 WebView，不修改系统/Clash/电脑网络。已在现有安卓1加载到 RoyaleAPI 的 Cloudflare 真人验证页，未代用户勾选验证；**尚未实测网页登录→下载→播放全链路**。内置浏览器不共享 Edge 登录；Google 登录可能不支持，不能通过导入 Cookie 或绕过验证解决。

找到完整 RoyaleAPI Replay 详情页后点「播放本页回放」，才读取该页 HTML 并调用同一个手机本地播放服务。不读取密码或 Cookie，不设置 JS→root 接口，不加载本地 HTML 的脚本。网址与 HTML 中的回放编号必须相同，全部源事件保留，统一延后20 tick仍只施加一次。

已移除不再需要的 ACCESS_NETWORK_STATE；本地解析/编译/播放仍无需网络。原有独立播放实测见下文；最新悬浮卡整局复测见上文。系统悬浮卡授权不等于 root 授权，二者分别由用户明确允许。

## 独立运行迁移（进行中）

控制台新增「检查手机独立运行环境（已有 root）」：检查代码在 Android 内运行，不调用电脑桥接。先读取已安装 APK 的 ARM64 `libg.so` 并校验完整 SHA256；不匹配时连 root 也不请求。用户明确授权后才调用已有 `su`，仅检查 root UID、游戏代际、现有调试器占用和内存文件打开权限。不附加游戏，不写游戏内存，不发布回放。

当前设备结果：用户已明确授权，并手动将本控制台的「超级用户」策略设为始终允许。设备实测已通过完整客户端哈希、应用自己的 root 授权、进程代际、调试器未占用及内存文件打开检查。ADB root 不能替代应用自己的授权；本项目没有修改全局 root、SELinux 或其他应用权限。

已迁入手机的实际链路：

1. 官方 PSF Android Python3.14.8 内嵌运行时，安装时校验归档和逐文件 SHA256；HTML 不执行脚本。
2. 与电脑相同的完整解析器、卡牌编号解析、原始事件/时间/坐标/形态/技能保留。
3. 手机根据已安装 APK 完整哈希重新绑定当前游戏进程，直接读取源对局所需卡牌等级与四种塔楼目录，保留原观察器的重复读取及64KiB预算。
4. 手机从自己的已安装 APK 生成并核对地图资源；重新核对原生 worker 和系统加载器导出，生成本场 preparation。它仍是初始化请求，不是可直接发布的完整录像。

真实 HTML 设备测试保留154条事件、13种源卡牌、4种塔楼目录，无电脑后端、无游戏内存写入、无调试附加。界面的「本机完整解析」和「本机原生准备（不播放）」可单独使用；解析/准备成功不代表独立播放完成。

手机工具链已完成实际 C++17 编译、静态 C++ 运行库校验、调试器加载，以及只对我们自己创建的合成子进程进行函数调用/脱离测试（LLDB21.1.8 / Python3.14.8）。未附加游戏。工具仅在本控制台私有目录运行；没有安装 Termux 或写入其目录。

## 当前使用方法

1. 安装本项目生成的 `build/royale-replay-android-debug.apk`，打开「安卓回放控制台」。不要卸载或重签游戏。
2. 把自己保存的完整 RoyaleAPI HTML 放进安卓的下载目录，在控制台点「选择完整 HTML」。原始 HTML 私有保存；仅做事件预检时不会启动游戏。
3. 电脑在项目根目录运行：

   ```bash
   python3 android-adaptation/scripts/companion.py --backend official-web-replay --enable-native --seconds 1800
   ```

4. 安卓显示「后端已配对」后，选择倍速并请求原生播放。完整校验和原生准备仍由电脑执行，画面在现有官服客户端显示。收到排队回执不是播放成功。
5. 「停止 / 安全取消」仅针对本控制端发起的任务。电脑连接中断、配对过期或原生任务失败时，不自动重试；保留现场供检查。

配对最长两小时，默认半小时；需要时启动新会话。重复开启电脑桥接器会被拒绝，不替换现有会话。此电脑桥接器目前仍是 macOS 版本，不能当作 Windows 后端。

按钮变灰时会直接显示具体条件：未连接电脑播放服务、正在导入、尚未选择真实 HTML、自检样例不可播放、或任务未结束。重启安卓不会自动启动电脑服务，需要电脑会话仍在运行。

点击播放会自动切回已安装的官服客户端；电脑端确认游戏在前台、进程代际未变后才开始原生准备。加载中请保持游戏前台。已提交场景但校验失败时进入 `needs_review`，保留现场并禁止重复提交，不能靠清空错误提示绕过。

## 构建与权限说明

推荐安装官方 Android SDK 平台后，通过 `scripts/build_apk.py --jdk <JDK17> --build-tools <目录> --android-jar <android.jar>` 构建。工具不自动接受 SDK 许可。

本机离线实验因 SDK 下载失败，使用 `--framework-res <已有模拟器的framework-res.apk>` 和最小编译声明构建，已实际安装运行；声明只用于编译，不作为 Android 实现打入 APK。正式发布应改用官方 SDK 再构建验证。模拟器资源、游戏、个人 HTML 和签名密钥不随项目分发。

电脑桥接优先用 Android 的 `run-as` 访问本应用私有文件。当前精简 MuMu 缺少此命令，因此仅在已有授权 ADB root 的测试环境中使用 `native/app_files.cpp`，先降至本应用 UID 再读写限定的任务文件。不为设备提权，不改 SELinux，不访问其他应用数据。普通未授权手机不满足此条件时会明确停止。

本地测试：`python3 -m unittest discover -s android-adaptation/tests -v`。设备测试：`adb -s <所选实例序号> shell am instrument -w local.royale.replay.android/.ReplayTests`。
