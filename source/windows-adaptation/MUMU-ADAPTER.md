2026-10-19，本机 Windows x64、MuMu 6.6.4.0、实例 0、Android 12 实测。

- Edge 的“RoyaleAPI → 官服回放”插件已加载，本地消息桥接已注册。点击插件即可把当前回放页发送到控制台，在已有 MuMu 实例中播放。
- 完整示例 `02JYPP0QJPPJ` 的 127 条动作全部保留、原生预演执行成功，回放 JSON 重新导入后的 127 条动作也全部通过。
- 原生战场画面已实际显示并播放至终局，终局 tick 5926；仍在场的五座塔血量均与网页一致。
- 播放结束后控制台自动显示，提供“重新回放 / 退出回放”，并刷新游戏客户端。已实测客户端进程更换及按钮恢复。
- 播放中强制关闭客户端后，控制台自动清除播放归属、结束等待并恢复操作。已在第二次实际播放中强退验证；测试后重新打开游戏并确认回到大厅。
- 网页插件不启动网络监听服务。它只在点击时读取当前 RoyaleAPI 回放页，通过浏览器原生消息和本机队列传递。

## 安装位置

控制台：`MuMuReplay/Start-Replay.cmd`。

插件：`MuMuReplay/网页插件`。本机 Edge 已由用户手动加载。

Windows 桥接：`MuMuReplay/browser-bridge`，仅注册当前 Windows 用户的 Edge 原生消息宿主 `local.royale.htmlreplay`。

## 实现与边界

- 后端显式选择 `mumu-nativebridge-v1`。x86_64 LLDB 经已初始化的 NativeBridge 调用 ARM64；默认原生 ARM64 后端不放宽架构约束。
- 绑定当前系统库、游戏库完整 SHA-256、JNI 锚点、进程代际及工作线程，校验所有组件的实际映射和函数字节。
- 适配 MuMu 的只读 ARM 代码映射、多命名空间代理库，以及 Windows ADB 二进制标准输入的 Ctrl-Z 截断问题。
- 原始游戏适配 C++ 源文件保持不变。编译时生成受记录的 MuMu 映射校验及有类型的系统函数转发，不改游戏包或签名。
- 空任务已由预期工作线程执行并销毁。队列缓冲及互斥调用使用当前游戏实际导入的系统函数。
- 无法仅凭 x86 栈证明 ARM 返回地址已离开组件，因此释放私有数据后保留组件代码到客户端退出；不会凭宿主栈错误卸载。
- 已提交的任务不自动重发；失败、超时和未知所有权均保留原句柄。停止或完成只刷新经即时证明由工具拥有的本地回放客户端。
- 后台子步骤使用独立输入和隐藏窗口，避免与控制台消息管道相互等待。客户端进程退出时终止本轮等待；普通准备步骤有明确超时。
- 示例沿用原项目统一延后 20 tick 的时序规则，不叠加新延迟。
