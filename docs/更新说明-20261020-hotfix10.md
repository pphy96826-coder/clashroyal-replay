# Android 2026.10.20-hotfix10 更新说明

本次只更新 Android（versionCode 2026102010）。macOS / Windows 继续使用 [hotfix3](https://github.com/pphy96826-coder/clashroyal-replay/releases/tag/replay-sync-20261019-hotfix3)。浏览器桥接脚本没有改动，已经装在 Edge 里的版本可以继续用。

## 全程在游戏内操作

- **Edge 小窗**：悬浮控制台里的「小窗打开 Edge（RoyaleAPI）」会把你自己的 Edge 以系统小窗口打开，浮在游戏下半屏，所以 Google 和 RoyaleAPI 的登录都保留。小窗可以拖动标题栏，也有 ⤢ 和 ✕ 按钮。普通接口无法把已经全屏的 Edge 改成小窗，所以这一步借用控制台现有的 root 执行固定命令（`am start --windowingMode 5`、`am task resize`），不读取 Edge 里的任何内容；没有 root 时就按普通方式打开。
- **浏览器桥接直接进悬浮窗**：在 Edge 点「在安卓控制台播放」后，不再打开控制台。回放直接出现在悬浮面板里，可选「立即播放 / 加入队列 / 忽略」。收到链接本身永远不会自动播放。悬浮窗没开时会自动启动；没有悬浮窗权限时，仍然打开原来的确认页。
- **播完不回控制台**：终局核验后，悬浮面板会自动展开，可以直接「重放本场 / 退出回放」。退出后游戏会自动重新打开。实际开始步进后，面板也会自动收起，不挡战斗画面。

## 队列提前准备

- 回放一加入队列就自动开始准备：读取资源、校准发牌、预演整局、核对指令。每一行右侧显示自己的状态：等待准备 / 准备中·… / ✓ 已就绪 / 排队中。
- 已就绪的回放点「播放下一个」后只剩加载画面，实测约 14 秒开播，原来约 50 秒。上一场结束、客户端回到大厅后，队列里的下一场也会自动准备。
- 提前准备只做准备，绝不会自动开播：只有你点播放时，才会写入开播信号。自动准备只在游戏已经运行、没有其他任务占用时进行。同一场在同一个游戏进程里只自动尝试一次，也从不自动重启游戏。
- 已就绪的回放最多等 2 小时。只有队列里提前准备的回放有这个宽限，其他播放请求仍是 10 分钟。
- **限制（由回放运行时决定）**：准备一旦进入原生执行，被取消后只能靠结束那个游戏进程来释放。因此：
  - 删除已就绪的那一行，需要 5 秒内连点两次确认。
  - Edge 发来的「立即播放」和「重放上一场」会先安全取消已就绪的回放，再仅重启那一个游戏进程（重启前核对 pid 和启动时间），然后自动准备并开播。按钮上会标出「需重启游戏」。
  - 对其他行「置顶」不会打断已就绪的那场，它会排在已就绪那场的后面。
  - 改倍速只影响之后准备的回放；已就绪的行如果倍速不同，会在状态里标出它的倍速。

## 更新方法

下载 `Android-Replay-20261020-hotfix10.apk`，用 `SHA256SUMS.txt` 核对后直接覆盖安装，不要卸载，也不要清数据。装好后打开一次控制台，悬浮按钮就会出现。

本版更新了内置回放运行时（`device_playback.py`）。如果更新时有回放正处在“已就绪”状态，装好后它会显示「未就绪·播放时重新准备」；点「播放下一个」会先重启一次游戏客户端，再准备并开播。

## 验证范围

- 本地 149 项回归测试通过，APK 的 v2/v3 签名已核验。
- 在 MuMu（Android 12）实例上实测通过：
  - Edge 小窗：已有小窗时、Edge 任务已关闭时都能正常打开；把已全屏的 Edge 改成小窗所用的命令手动执行验证过。
  - Edge → 悬浮窗 →「立即播放」完整播放一局，然后「退出回放」。
  - Edge →「加入队列」→ 自动准备 → 约 14 秒开播。
  - 战斗中「添加 HTML」，结束后自动准备；一次多选两个文件。
  - 已就绪时改倍速；两次确认删除已就绪行，随后重启并自动准备下一场。
  - 被取消后点「播放下一个」：重启、准备、开播约 50 秒。
- **没有实测**：「重放本场」「重放上一场」、已就绪时从 Edge「立即播放」另一场、已就绪时置顶其他行（只有源码测试）。朋友的虚拟大师也没有验收这一版。
- 结束后仍采用“核验归属后重启客户端”的兜底方案，不是免重启返回大厅。
