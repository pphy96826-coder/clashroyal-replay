# Hotfix1：种子搜索与塔血比较

仅当完整指令中实际打出猎人，或实际使用可明确归属骷髅帝王的技能，且终局仍有差异，才启用种子重试。带在卡组中但未使用、其他英雄的技能、普通对局的血差都不会触发。多个技能单位导致无法识别归属时不猜测。

## 塔血不是双方总量之差

按所属玩家分别比较国王塔、公主塔记录，再累计绝对差。双方不会互换，国王塔不参与公主塔配对，也不会使用总血量相减来抵消差异。

## 固定顺序与毁塔后的压缩列表

双塔存活时保留固定玩家视角顺序：princess0 为玩家左侧，princess1 为玩家右侧。当前原生绑定中 owner1 的玩家左塔 x=3500，owner0 的玩家左塔 x=14500；这是两名玩家朝向相反的坐标对应。比较器不会排序，也不会试交换后挑较小的血差。

原始战报字段 princessTowersHitPoints 是可变长数组。公开的原始 1v1 样本存在只有 [1982] 的记录，双塔样本还存在 [3,549]，因此不能把它理解为总是降序，也不能让单元素记录证明毁塔侧。RoyaleAPI hp-popup 将缺少的第二项显示为 0。

本机的两份已完成记录也显示：一份上方剩 x=3500 的塔，另一份剩 x=14500 的塔，网页均把剩余血量放在 princess0、princess1=0。修复据此在单塔存活时核验剩余血量和毁塔数量，并保留“毁塔侧未核定”；不会凭血量反推原局侧别。

刚才 106 条指令的回放：对方网页为 4824 / 729 / 0，原生国王塔 4824、公主塔 x=14500 为 729、x=3500 有明确原生摧毁回执。旧代码把 729 与已经摧毁的塔错配，算出 1458。新版本核对战报剩余血量为 0 差，同时不宣称原战报证明了毁塔侧。

## 验收

dev24 使用同一原始 HTML 重新完整执行 106 条指令并播放，原生 JSON 往返通过，终局 tick 5520，种子重试 0 次，战报血差 0。客户端刷新并返回大厅。42 项针对性主机检查和 60 项控制台设备检查通过。双塔存活却对调两项血量的测试仍失败，双方差异不能抵消；无原生摧毁回执的缺塔仍为未知。

之前发布中的 dev21“塔血差 1458、仅胜负相同”受旧槽位解释影响，不能当作随机性证据。其停止按钮的实际点击、原生核验和播放行为记录仍保留为历史记录。
