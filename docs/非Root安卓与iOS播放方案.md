# 非 Root 安卓与 iOS：可能的播放方法

本文说明没有 Root 的安卓手机、iPhone 和 iPad 可以用哪些方式看官服回放，以及每条路线目前的验证状态。结论先放在前面：

| 你的设备 | 现在就能用 | 可以尝试（未验证） | 不可行 |
|---|---|---|---|
| 非 Root 安卓 | 电脑跑回放、手机远程观看或操作；录成视频再看 | 手机虚拟机（客体自带 Root）；带 Root 的云手机；自行解锁 Root | 只装控制台 APK；Shizuku / 无线调试；改签游戏 APK |
| iPhone / iPad | 电脑跑回放、手机远程观看或操作；录成视频再看 | 带 Root 的云手机 | UTM 本机跑安卓（理论可行，实际太慢）；越狱后直接调试 iOS 版游戏（需要整套重做） |

---

## 1. 为什么一定要 Root（或电脑上的模拟器）

回放不是播放一段视频，而是让**官服客户端自己的原生引擎**把整局重新算一遍。控制台需要：

1. 以调试器方式附加到游戏进程；
2. 把回放组件载入游戏进程，用原生接口提交出牌和技能；
3. 读取游戏内存，核对开局发牌、塔血和终局。

安卓只允许 **root 进程**或**调试版（debuggable）应用**被其他进程这样附加，而官服游戏不是调试版。本项目不修改、不重新签名游戏 APK：这样做违反服务条款，签名一变就无法正常登录和更新。所以需要一个能拿到 root 的安卓环境，而电脑上的 MuMu 模拟器正好满足。iOS 上同理：附加其他 App 的进程需要越狱。

## 2. 非 Root 安卓手机

### 2.1 推荐：电脑跑回放，手机远程观看或操作（已验证可用）

回放在 Windows 或 Mac 的 MuMu 里运行（已验证），手机只负责看和点。

1. 先按[全平台安装教程](全平台安装教程.md)在电脑上装好，确认电脑上能正常播放一局。电脑本身播不了时，远程软件修不好。
2. 两端从官方渠道安装远程软件，任选其一：
   - **Moonlight + Sunshine**：电脑装 Sunshine（主机端），手机装 Moonlight（客户端）。专为游戏串流设计，画面流畅、延迟低，推荐用来看对战。
   - **RustDesk**：通用远程桌面，设置简单，适合点按钮、选文件。
   - 其他远程桌面也可以，但普通远程桌面对模拟器的 3D 画面可能卡顿或黑屏。
3. 在手机上打开远程画面，直接操作 MuMu 窗口里的**游戏内悬浮控制台**：开 Edge 小窗、加入队列、播放下一个、重放/退出，全部都在游戏画面里完成。
4. 卡顿时先降低串流分辨率或帧率，720p / 30fps 可作为起点。

注意：远程软件本身不在本项目的验证范围内。不要把 ADB 端口、远程桌面端口暴露到公网，也不要为此关闭防火墙。只在局域网用，或使用软件自带的加密中继。

### 2.2 最简单：录成视频，在手机上看（任何设备都可以）

在电脑上播放回放时录屏，然后把视频发到手机上看。用 MuMu 自带的录屏，或电脑上的录屏软件（如 OBS）即可。缺点是只能看、不能操作，每局要录一次。

### 2.3 可以尝试：手机里的安卓虚拟机（客体自带 Root）

外层手机保持不 Root，在“虚拟大师”、VMOS Pro 等虚拟系统里，用它自带的 Root 运行游戏和控制台。

- **状态：尚未成功。** 朋友的虚拟大师（Android 11）上，hotfix4–8 陆续定位到执行器启动、调试器执行内存申请、内存映射格式等问题，至今还没有完整播放成功的记录。
- 做法：在**虚拟系统里**（不是外层手机）安装 APK，游戏在大厅时试播一次。失败就点“导出诊断”，把 ZIP 私下发来。
- 不同虚拟机产品和 ROM 差别很大：图形驱动、内核、调试实现都会影响结果。没有验证过的“一键 ROM”不等于能播。不建议为此购买付费 ROM 或长期订阅。

### 2.4 可以尝试：带 Root 的云手机

一些云手机服务可以开启 Root。游戏和控制台都跑在云端安卓里，手机用服务商的 App 或网页观看。

- 需要满足：ARM64 的 Android 10–12、可开启 Root、可以安装第三方 APK、有 GPU 渲染。
- **状态：未测试。** 能不能用取决于服务商的系统；验收方法与手机虚拟机相同：试播一局，失败就导出诊断。
- 风险：游戏账号会登录在第三方云端，请自行评估账号安全，并遵守服务商条款。

### 2.5 可以尝试，但不推荐：给手机本身解锁 Root

解锁 Bootloader 后用 Magisk、KernelSU 等获取 Root，手机就等同于“已有 Root 的安卓”，按普通安卓教程安装即可。

- **状态：只在模拟器上验证过 Root 路线，没有在真实手机上验证。**
- 代价：解锁会清空手机数据；可能失去保修；部分银行、支付类应用会拒绝运行；不少品牌或机型无法解锁；游戏客户端也可能检测 Root 环境。不建议在主力手机上这样做。

### 2.6 不可行的方案（以及原因）

- **只在普通手机上装控制台 APK**：没有 Root，无法附加到游戏进程，控制台会停在准备阶段。
- **Shizuku / 无线调试（ADB）**：只能拿到 shell 权限，安卓不允许 shell 附加非调试版应用的进程。
- **把游戏改成调试版或重新签名**：违反服务条款，签名变化后无法正常登录和更新。本项目不提供，也不支持。

## 3. iPhone / iPad

### 3.1 推荐：电脑跑回放，iPhone 远程观看或操作（已验证可用）

做法与 2.1 相同。iOS 上有 **Moonlight**（配合电脑上的 Sunshine）和 **RustDesk** 客户端。iOS 版 RustDesk 只能控制别的设备，不能被控制，正好符合这个用法。在远程画面里直接点游戏内悬浮控制台即可。

### 3.2 录成视频 / 云手机

- 录屏方法同 2.2，在 iPhone 上看视频即可。
- 带 Root 的云手机（2.4）如果提供 iOS 客户端或网页，也可以在 iPhone 上观看。同样未测试。

### 3.3 理论可行、实际不可用：在 iPhone 上用 UTM 跑安卓

UTM 可以在 iOS 上运行其他系统，思路是在里面装 ARM64 安卓，再装游戏和控制台。但是：

- App Store 版 **UTM SE** 没有 JIT，只能逐条解释执行，跑 3D 游戏慢到无法使用；
- 完整版 UTM 需要侧载并另外开启 JIT。即便如此，iOS 上一般没有硬件虚拟化，仍要模拟整套安卓，图形也只能软件渲染；
- 还要自己找可合法使用、带 Root、能运行游戏的 ARM64 安卓镜像。本项目没有提供，也没有验证过这样的镜像。

**结论：只适合研究，不适合拿来看回放。**

### 3.4 需要整套重做：越狱后直接驱动 iOS 版游戏

越狱后理论上可以附加 iOS 版游戏进程，但本项目所有原生绑定都是针对**安卓版客户端**的特定库文件（按完整哈希核验，版本 38.4.2）做的：函数位置、对象结构、加载方式都不同。iOS 版需要从头逆向一遍。加上当前 iOS 版本的越狱条件很有限，**这条路线没有可用实现，目前也不计划做。**

---

## 4. 怎么选

1. 想马上看：电脑装好 MuMu 和本项目，手机用 Moonlight 或 RustDesk 远程看（2.1 / 3.1）。
2. 只想看，不想操作：电脑上播放并录屏（2.2）。
3. 愿意帮忙测试：手机虚拟机（2.3）或云手机（2.4）。试一次，失败就导出诊断发来，不要反复重试，也不要清游戏数据。

更详细的安装与远程设置见[全平台安装教程](全平台安装教程.md)第 6、7、12、13 节。
