## 1. 问题：一局回放的结局与 RoyaleAPI 页面相反

有反馈称 [Mohamed Light 的对局列表](https://royaleapi.com/player/G9YV9GR8R/battles) 中，有一局模拟结果和页面不一致。我们把模拟器上播放过的所有记录逐一和页面比对：

- 共 11 场不同对局、24 次播放。其中 10 场（21 次播放）的终局六座塔血量与页面**完全一致**。
- 只有 **02CY92YUQPY9**（Mohamed Light 对 CAL Sub，3:18，页面上 Mohamed 获胜）不符，而且 3 次播放的结局完全相同：

| | 页面 | 模拟（hotfix10） |
|---|---|---|
| Mohamed（红方） | 三塔完好 | **左公主塔被摧毁** |
| 对手（蓝方） | **右公主塔被摧毁**，国王塔 2151 | 三塔都在，国王塔 4824（无伤） |
| 结果 | Mohamed 加时 1:0 获胜 | Mohamed 加时 0:1 落败 |

页面上的 58 条操作（56 次出牌、2 次技能）全部被原生引擎接受，没有丢弃或改写。

## 2. 原因

### 2.1 随机技能依赖页面没有的随机种子

这局对手使用了**骷髅帝王**，在 163 秒和 181 秒各发动一次技能。骷髅帝王召唤的小骷髅位置和数量与引擎随机数有关，而随机数由对局的随机种子决定。**RoyaleAPI 页面只有出牌、技能时间和终局塔血，没有随机种子。** 此前所有回放都使用同一个固定种子（1784463263）。没有随机技能的对局不受影响，所以其余 10 场都完全一致。

我们换了 24 个、后来 60 个不同的种子来跑这一局，结果证实了这一点：

- 结局随种子剧烈变化：有的种子红方左塔被推，有的蓝方左塔被推，有的蓝方国王塔被推。
- 种子 1929012094 下，红方两座公主塔的血量（2037、2146）与页面**分毫不差**，说明除了随机部分外，其余过程都是正确的。
- 很多种子会在页面最后几张牌之前提前结束（真实对局还在出牌），或者在页面发动第二次技能时骷髅帝王已经阵亡。这些种子与页面矛盾，会被直接淘汰。

### 2.2 校验流程漏掉了终局比对

准备阶段本来就会完整跑一遍对局，得到终局塔血。但旧代码**只有在英雄技能目标有歧义时**才会拿它和页面比对；其他对局从不比对，却显示“整局校验通过”。日志里的 `final_hp_matched: false` 实际含义是“没有比对”，而不是“比对失败”。

## 3. 本版改动

1. **每场都比对页面终局。** 准备完成后，用同样的规则把模拟终局与页面六座塔逐一对照：塔被摧毁记为 0；国王塔倒下时同侧公主塔一并记为 0；某座塔既不在场上、又没有摧毁证据时记为“未知”，不会猜一个匹配。
2. **不一致时搜索随机种子。** 由回放的源哈希固定生成 60 个 int32 种子，所以同一份 HTML 每次尝试的种子都相同、可复现。对每个种子：
   - 重新校准原生开局发牌，保证开局手牌与页面一致后才执行任何指令；
   - 完整执行全部指令（含原有的技能目标歧义搜索）；
   - 只有指令全部执行完的结果才参与比较。
3. **按优先级选出最接近页面的结果**，原种子也参与比较：
   1. 完全一致：六座塔血量都相同，找到后立即停止搜索；
   2. 被摧毁的塔相同：胜负和皇冠数也相同，再取塔血差最小的；
   3. 只有胜负相同；
   4. 不符。
4. **如实显示。** 选中的种子会用于真正播放（随最终录像写入），状态里记录 `page_match`、`page_hp_difference`、`random_seed`、`random_seed_inferred`、`seed_attempts`，完整搜索记录在任务目录的 `seed-search.json`，导出诊断时一并带上。

## 4. 界面怎么看

队列每行右侧和悬浮面板标题会显示：

| 显示 | 含义 |
|---|---|
| ✓ 已就绪 | 终局六塔与网页完全一致（可能是换了种子后一致，面板会注明） |
| ✓ 已就绪·终局近似 | 胜负和被摧毁的塔与网页一致，塔血有差别；面板写明合计相差多少 |
| ⚠ 已就绪·仅胜负同网页 | 谁赢一样，但倒下的塔不同 |
| ⚠ 已就绪·与网页不符 | 尝试 60 个种子后仍不一致；可以播放，但过程与原局不同 |
| 准备中·匹配随机种子 | 正在尝试种子，面板会显示进度和当前最接近的等级 |

**换出来的种子是推断的，并不是原局的种子；“终局近似”也不代表过程与原局完全相同。** 只有“✓ 已就绪”且没有注明换种子时，才是在原有规则下完全对上。

## 5. 耗时

- 与页面直接一致的对局（目前绝大多数）不额外花时间。
- 不一致的对局，每个种子约 10 秒（校准发牌加完整执行），60 个最多约 11 分钟。这一步在加入队列后的后台提前准备中完成，行右侧会显示进度。需要立即播放时，等待时间也会相应变长。
- 找到完全一致的种子会立即停止。

## 6. 实测结果（MuMu Android 12）

02CY92YUQPY9 共尝试 60 个种子：

- 42 个与页面矛盾被淘汰：提前结算、技能无目标或未执行完；
- 18 个完整执行：13 个结局不同，4 个仅胜负相同，1 个被摧毁的塔相同，0 个完全一致；
- 选中种子 −1350491712，再进入游戏实际播放，结束于 3861 tick（约 193 秒；页面为 198 秒）：

| | 页面 | hotfix11 游戏内实际终局 |
|---|---|---|
| 对手 | 国王塔 2151，左塔 1630，**右塔被摧毁** | 国王塔 4824，左塔 926，**右塔被摧毁** |
| Mohamed | 国王塔 4824，左塔 2037，右塔 2146 | 国王塔 4824，左塔 2144，右塔 **2146** |

结局与页面相同：Mohamed 1:0 获胜，倒下的是对手右塔。塔血合计相差 3484，与准备阶段的预测一致。

本地 153 项回归测试通过，新增的测试覆盖了种子计划可复现、每个种子先校准发牌、只接受完整执行的结果、原种子参与比较、完全一致立即停止、终局分级规则（含摧毁、国王倒下、未知塔），以及“未匹配时不显示校验通过”。

## 7. 限制

- 页面没有原局种子，**完全还原**带随机技能的对局只能碰运气：这局 60 个种子里没有完全一致的。理论上种子空间约 43 亿，穷举不现实。
- 目前只观察到骷髅帝王的召唤会造成这种差异。其他依赖随机数的机制如果存在，也会被同一套比对发现，并走同样的种子搜索。
- 对局结束后仍采用“核验归属后重启客户端”的兜底，不是免重启返回大厅。
- 朋友手机上的虚拟大师还没有验收这一版。

## 8. 升级

APK 发布后，覆盖安装即可，不要卸载或清数据。如果更新时队列里有“已就绪”的回放，装好后它会显示「未就绪·播放时重新准备」；点「播放下一个」会先重启一次游戏客户端，再准备并开播。
