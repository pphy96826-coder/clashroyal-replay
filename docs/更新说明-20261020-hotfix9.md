# Android 2026.10.20-hotfix9 更新说明

本次只更新 Android（versionCode 2026102009）。macOS / Windows 仍是 [hotfix3](https://github.com/pphy96826-coder/clashroyal-replay/releases/tag/replay-sync-20261019-hotfix3)，本次不用更新。

## 新增：游戏内悬浮控制台

- 打开一次控制台后，屏幕边缘会出现一个圆形「回放」按钮。在游戏里点它可以展开或收起悬浮控制台，按住可以拖到任意位置。通知栏的「回放悬浮控制台」也能展开或收起。
- 面板显示当前回放状态，提供这些操作：
  - 播放下一个、切换倍速
  - 停止当前回放：要连点两次确认，仍然只重启游戏客户端
  - 打开完整控制台、关闭悬浮窗
- 悬浮窗不抢焦点，只响应它自己范围内的触摸。游戏始终是前台，面板外的触摸照常交给游戏。
- 关闭悬浮窗后它不会自动再出现，可以在主控制台点「开启游戏内悬浮控制台」恢复。

## 新增：可编辑的待播队列

- 悬浮窗和主控制台都能管理待播队列：
  - 「添加 HTML」：用系统文件选择器，可以多选，选完回到原来的界面
  - 每一场都可以「置顶」（设为下一场）或「删除」
  - 「清空队列」：要连点两次确认
- 删除只移除队列里还没开始的那份副本，不影响正在播放的任务、已保存的回放和诊断记录。下一场正在开始时，队列暂时不能修改。
- 悬浮窗里的「播放下一个」和主控制台走同一套流程：由服务把游戏切到前台，并做同样的任务归属和场景校验。仍在占用现场的任务不会被覆盖。

## 一并公开：hotfix4–8 的安卓修复

这些修复此前只私下测试过，没有公开发布。hotfix9 包含了全部内容：

- hotfix4：能证明执行器还没进入原生执行就已退出时，解除旧请求的占用；任务目录不存在时，诊断导出也会收集启动日志。
- hotfix5：原生调用改为绑定已核验的暂停主线程栈帧；修正把 `handle` 误判成手牌故障的问题；执行前被拒绝时，只在严格条件下记录"已安全释放"。
- hotfix6：失败后只读采集调试器兼容性证据，包括 mmap/dlopen 地址、系统库路径映射和寄存器能否读取。
- hotfix7：内存映射改为严格的有界解析，格式异常最多重新读取三次，不跳过未知行。
- hotfix8：兼容一种已识别的不完整系统属性映射记录（只作为诊断保留，不加入可读内存范围）。

这些修复都不能证明虚拟大师等手机虚拟机已经可以完整回放。

## 更新方法

下载 `Android-Replay-20261020-hotfix9.apk`，先用 `SHA256SUMS.txt` 核对，再直接覆盖安装。不要卸载，也不要清除数据。装好后打开一次控制台，悬浮按钮就会出现。仍然需要兼容的已有 Root 调试环境。

## 验证范围

- 本地 146 项回归测试通过；APK 的 v2/v3 签名已核验。
- 在 MuMu（Android 12，1080×1920）实例上覆盖安装后实测了以下项目，数据完整保留，没有崩溃：
  - 在桌面和游戏大厅里显示、拖动、展开和收起悬浮窗
  - 添加 HTML（可多选，选完回到原界面）、删除（队列副本同时删除）
  - 置顶，以及恢复原来的顺序
  - 清空队列的二次确认（只点一次时队列不变）
  - 悬浮窗显示期间，游戏一直是前台活动
- **没有实测：**从悬浮窗发起「播放下一个」或「停止回放」完成一整局。这两个操作与原控制台按钮共用同一套代码和校验。朋友手机上的虚拟大师也没有验收这一版。
- 结束后仍采用"核验归属后重启客户端"的兜底方案，不是免重启返回大厅。
