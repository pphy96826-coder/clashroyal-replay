# Android 2026.10.21-hotfix37 更新说明

本次只更新纯安卓适配（versionCode 2026102137，源码 `source/android-native/`），包含本地版本 hotfix12–37 的全部改动。完整配置步骤见 [安卓适配图文教程](README.md)。

**Mac 适配改为 MuMu 安卓路线。**原 macOS 桌面版（源码 Skill）已停用并从仓库移除。Mac 用户在 MuMu 模拟器 Pro 的安卓 12 实例里安装本 APK 即可，与手机用同一个安装包，Mac 本身不再需要 Python 或 NDK。Windows 用户使用另一套独立适配 [Windows + MuMu 一体版](../docs/mumu-android/安装教程.md)，不受本版影响。

## 1. 终局比对与随机种子

- **随机种子只在卡组含骷髅之王或猎人时搜索。**以前只要终局塔血和网页不一致，就自动尝试最多 60 个随机种子，没有先判断这局是否有随机性。现在只有任一方卡组含这两张卡时才搜索，其他对局一律保留原种子，终局不一致时如实标出。
- **搜索可随时停止。**点「停止匹配，用当前最接近的开播」，当前这个种子跑完后就用最接近网页的结果继续。
- **英雄技能目标必须完全一致。**技能有多个合法目标时，只采用整局终局与网页完全一致的分支。原种子下没有一致的分支、且卡组含骷髅之王或猎人时，每个候选种子下都重新做同样严格的技能检查；仍找不到就不播放。
- **两套终局判断合并为一套逐塔规则。**塔还在用实际血量；观察到被摧毁记为 0；本方国王塔倒下时公主塔记为 0；以上都没有证据时记为“无法完整比对”，不再当作“不符”，也不会触发种子搜索。修正了“国王塔已毁、公主塔已移除”在两套规则下结论不同的问题。
- **网页左右公主塔的顺序不可靠，已按血量证据配对。**RoyaleAPI 页面的 `princess0` / `princess1` 并不总是对应场地的左 / 右：02RYPY228YCQ 中上方玩家的两座公主塔在网页上是反的（网页 579 / 0，实际是左塔被摧毁、右塔 579），同方向的 002YQ9LLV989 与 02CY92GGGCLG 却是正的。以前这会把被摧毁的塔算到另一侧，判成“不符”，导致该局所有技能分支都“未通过整局校验”而无法播放。现在每位玩家的两座公主塔按网页原顺序比对；只有交换后**非零血量的完全匹配更多**时才交换（单凭被摧毁的塔不能决定左右），并在 `page-comparison.json` 里逐塔记录 `page_order`（direct / swapped）。用保存的诊断复核：02RYPY228YCQ 有 4 个技能分支在交换后六塔完全一致，其余分支仍判为不一致；之前一致的对局不受影响。
- 诊断新增 `page-comparison.json`，逐塔列出网页血量、模拟血量、判断依据和网页左右顺序。

用 13 份诊断里能解析的 27 次完整预演复核：新旧规则结论完全一致（4 次完全一致、12 次仅胜负相同、11 次不符，大多为换种子的试跑），162 座塔没有一座落入“无法完整比对”。

## 2. 皇家厨师等塔楼兵种（hotfix35–37）

使用皇家厨师塔的对局（例：08CY0LPY90V0）以前一预演就失败，提示“excessive observation”。原因有三层，都已修复：

1. **原生塔血观察器只认标准塔编号。**初始化能识别皇家厨师塔，但预演里的塔血观察器只接受国王塔 / 公主塔的编号（35000000 / 35000001），漏掉了厨师一方的三座塔，凑不满“必须找到六座塔”的检查，于是没有生成预演记录。现在观察器接受本局准备时绑定的六座塔编号（皇家厨师、加农炮手、匕首公爵夫人等所有塔楼兵种都按各自编号识别），标准塔仍照常识别。
2. **错误提示有误导。**外层把“没有生成记录”报成了 excessive observation。现在会如实提示“原生执行未生成记录（size 0）”或给出实际大小，并记录在诊断里。
3. **终局比对漏认被摧毁的厨师塔。**原生记录里存活塔的编号是无符号数（3191249505），被摧毁塔的编号却是有符号数（−1103717791），两者是同一个编号。比对时现在统一按无符号 32 位比较；“国王塔倒下则公主塔记 0”的规则也改为按本局实际的国王塔编号判断（皇家厨师国王塔是 1471932914）。

实机验证：08CY0LPY90V0（一方为皇家厨师塔）在虚拟大师里完整播放到终局。

## 3. 手机虚拟机（虚拟大师）兼容

测试环境：外层为非 Root 的 Android 14，里面运行虚拟大师 3.2.77 + Android 12 ROM 1039（客体自带 Root）。

修复：

1. 虚拟大师输出的内存映射表有截断行、重复段、空行和乱序匿名映射；只跳过可证明无害的行，且不把它们当作可读内存。
2. 虚拟机里调试器找不到 `mmap` 时，登记经过核验（文件哈希、内存字节、地址一致）的系统 libc。
3. `/data/user/0` 与 `/data/data` 的符号链接导致取消后无法释放、无法退出，改为按实际文件比较。
4. `/system/bin/am` 无法直接执行，改为经 `sh` 调用。
5. 长对局的源指令读取上限、虚拟机加载战斗场景的等待时间放宽；强制结束游戏后多等一下再确认进程已释放。
6. 出错原因写入任务目录并随诊断导出，即使虚拟机丢掉了命令输出也能看到。

**结果如实说明：**hotfix21 与 hotfix24 在虚拟大师里完整播放成功（02CY92GGGCLG，141 条指令，终局六塔与网页完全一致）。之后在同一虚拟机里多次失败，原因在虚拟机这一层：调试器无法暂停游戏或无法执行原生函数调用，同时虚拟大师弹出“core process crashed in the VM”。因此这条路线标为**实验性**。

## 4. 速度与界面

- 读取资源提速：单次读取只核对进程身份，完整的进程映射核对每秒最多一次；30 MB 游戏库的哈希按文件身份缓存。虚拟大师里从约 2 分钟降到约 6 秒，安全检查不减少。
- 悬浮面板始终显示「小窗打开 Edge 浏览器」。
- 新增「重置所有回放进程」防呆按钮（完整控制台和悬浮面板都有，5 秒内连点两次才执行）：结束所有回放执行进程、强制关闭游戏、归档当前任务记录；不删除队列、已保存回放、历史和诊断。
- 游戏没运行时点「播放下一个」会先自动打开游戏，等待大厅的时间延长到 4 分钟。
- 一场准备失败后不再自动反复重试，避免“游戏不断闪退重开”。
