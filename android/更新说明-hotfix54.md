# Android 2026.10.21-hotfix54 更新说明

本次只更新纯安卓适配（versionCode 2026102154，源码 `source/android-native/`），包含本地版本 hotfix38–54 的全部改动。完整配置步骤见 [安卓适配图文教程](README.md)。Windows + MuMu 一体版是另一套独立适配，不受本版影响。

升级方法：直接覆盖安装 `Android-Replay-20261021-hotfix54.apk`，**不要卸载或清除数据**，队列与记录会保留。

## 1. 同一场回放可以稳定复现

- **随机种子改为按“对局内容”生成。**以前候选种子由 HTML 文件的哈希决定。同一场回放的网页重新保存一次，文件里的时间戳等会变，种子列表就完全不同，上次完全一致的结果无法复现。现在候选种子由回放编号、双方卡组、每次出牌的卡牌 / 时间 / 位置决定，与网页保存了几次无关。
- **记住每场对局最接近的种子。**每次准备结束后，把这场对局最接近网页的种子记在本机，下次准备同一场时第一个就试它。完全一致过一次的对局，以后约 30 秒即可准备完毕。
- 实测：092PYR8PUC9R 第一次在第 7 个种子完全一致；把网页重新保存后再准备，第 1 个种子即完全一致，约 30 秒准备完毕，六座塔与网页完全相同。
- 注意：种子列表的计算方式变了，其他回放在本版第一次准备时试的种子会和以前不同；准备过一次后就会被记住。

## 2. 准备更快、搜得更准

- **英雄技能先选最接近的组合，再匹配随机种子。**卡组含猎人或骷髅之王时，在原种子下保留六座塔血差合计最小的完整技能组合，再按这个组合去试其他种子；其他卡组仍要求技能目标与网页完全一致。
- **分支定界剪枝。**塔血只会减少不会回升，所以预演到一半时，某座塔已经低于网页终局血量，就能算出这条分支最终至少差多少；已经不可能比当前最好结果更接近的分支直接放弃，不再跑到终局。
- **先筛选、后精修。**60 个种子每个只跑一次（固定技能组合）；只对最接近的 3 个种子做深入的技能搜索。原种子下没有任何可跑完的技能组合时，每个种子都会做自己的技能搜索。
- **跳过多余的发牌校准。**每个种子只做一次发牌探测，预测的发牌由正式预演自身核验，不一致时才补做校准（实测 60 个种子里没有一次需要补做）。
- 实测极端回放 02JYPPC02YUL（85 条指令、16 次英雄技能、3 次猎人）：准备时间从约 8.7 分钟降到约 7.6 分钟；以前一直卡在“正在启动本机任务”的种子搜索，现在能完整跑完。

## 3. 虚拟机与调试器的稳定性

- **调试器丢失游戏进程后自动重启游戏、继续准备。**手机虚拟机里调试器偶尔会丢失游戏进程（报“native process state 5”“Expression execution was interrupted: SIGSTOP”等）。这与回放内容无关。现在会释放该次尝试、重启游戏、回到大厅后从当前步骤继续，已完成的预演保留；只要两次重启之间有进展就继续。
- **游戏自身的运行时信号原样交还游戏处理**，不再因此中断预演或播放；我们组件内的异常仍会停止。
- **清除残留的暂停信号。**调试器中断游戏时偶尔会留下一个排队的暂停信号，之后把游戏冻住（看起来像“卡死”）。现在每次附加前、脱离后都会检查并恢复。
- **游戏短暂不在空闲大厅（原生返回码 30）或游戏任务队列拒绝任务时**：这两种情况下原生组件什么都没做；以前我们的程序没先卸载组件就报错，组件留在游戏里，导致后续所有种子都被拒绝、自动恢复也无法进行。现在会正常卸载组件，等大厅稳定后重试这一步。
- 若某次尝试仍把组件留在游戏里，立即停止种子搜索并交给恢复流程，不再连续空跑。

## 4. 新增按钮

- **冻结卡顿的指纹服务（虚拟机卡顿时用）**：部分虚拟大师 ROM 的指纹服务会一直占满一个 CPU 核心，导致整台虚拟机卡顿、游戏启动时闪退。该按钮先测 2 秒，确认它确实在占用 CPU 才冻结（不结束进程，避免虚拟大师弹出“核心进程崩溃”），不改任何设置，虚拟机重启后恢复原状。
- **清理旧运行环境和任务记录**：删除旧版本解包的运行环境、过期任务记录和残留组件文件，保留当前运行环境、当前任务、队列和已保存回放。有回放在准备或播放时拒绝执行。实测在虚拟大师里释放约 2.5 GB。
- 「重置所有回放进程」现在也能结束被冻住的游戏。

## 5. 诊断记录

- 每次英雄技能的诊断会记录技能实际交给了哪个单位、当时有哪些候选单位，以及它们的位置，便于排查“技能给错英雄”。
- 准备记录里新增：每个种子的筛选 / 精修阶段、对局标识、记忆中的种子。

## 6. 常见的播放失败情形

| 现象（控制台或诊断里的提示） | 原因 | 处理 |
|---|---|---|
| 准备停在“等待游戏启动并进入空闲大厅”，约 4 分钟后取消 | 游戏没在运行，或停在加载界面、弹窗、对战中 | 先打开游戏、关掉弹窗、回到大厅，再点「播放下一个」 |
| 游戏开头显示“更新错误”，或启动后反复闪退 | 网络没通（MuMu / 虚拟机里的代理没开），或虚拟机卡顿（见下一行） | 确认代理已连接后点「重试」；仍闪退先按「冻结卡顿的指纹服务」 |
| 整台虚拟机很卡、“Virtual Master isn't responding” | 虚拟大师的指纹服务占满 CPU；或虚拟机存储将满 | 「冻结卡顿的指纹服务」；「清理旧运行环境和任务记录」 |
| “第 N 条技能的合法目标数为 0” 且整场“已探索的技能分支均未通过整局校验” | 用默认随机种子模拟时，网页记录里放技能的那一刻，模拟中没有可放技能的英雄（英雄已死或未充能）。只有卡组含猎人 / 骷髅之王时会换种子继续找 | 等种子搜索跑完；卡组不含这两张卡的对局目前无法自动修正，请导出诊断 |
| 终局“仅胜负相同”或“与网页不符”，但仍可播放 | 随机性（猎人散射、墓园骷髅落点等）或英雄技能分配与真实对局不同 | 可直接播放；想更接近可让种子搜索跑完。网页不含真实种子，结果为推断 |
| 同一场回放上次完全一致，这次却不一致 | 旧版按 HTML 文件生成种子，重新保存网页后种子列表变了 | 升级到本版；准备过一次后会记住最接近的种子 |
| “本机调试器无法执行原生函数调用”“stop for observation failed” | 虚拟机里调试器不稳定 | 本版会自动重启游戏继续；仍失败用「重置所有回放进程」后重试，或改用 MuMu |
| “自动恢复未通过归属检查”、游戏停在加载界面 | 失败时组件状态无法确认属于本次任务，为安全起见未自动关闭游戏 | 「重置所有回放进程」，重新打开游戏后再播，并导出诊断 |
| “source card level missing or unsupported: …” | 保存的网页不完整（例如页面未加载完、标题只是 RoyaleAPI 首页） | 在 RoyaleAPI 回放页完全加载后重新保存 / 发送 |
| “游戏库校验失败” | 游戏不是 38.4.2 审计版本或被修改 | 换成匹配的官方版本，不要关闭校验 |
| “游戏回放进程已结束” | 准备期间游戏被系统回收 | 重新打开游戏后再播 |

失败后请先点「导出诊断」：诊断里的 `error.txt` 写明失败原因，`page-comparison.json` 逐塔列出网页血量、模拟血量和判断依据，`seed-search.json` 记录试过的每个种子。

## 7. 验证

- 自动测试 226 项全部通过（`source/android-native/android-adaptation/tests`）。
- MuMu 模拟器 Pro（Android 12）实机：092PYR8PUC9R 六座塔与网页完全一致，重新保存网页后 30 秒复现并完整播放；02RYPY228YCQ 原种子完全一致并完整播放；02JYPPC02YUL（极端回放）完整播放，胜负与被摧毁的塔和网页一致、塔血合计差 1016。
- 虚拟大师（Android 12 ROM 1039）：调试器丢失进程后的自动重启、指纹服务冻结、存储清理已实机验证；hotfix54 的完整播放主要在 MuMu 上验证。

## 8. 已知限制

- RoyaleAPI 网页不包含真实随机种子，也不记录每次技能是哪个英雄放的；含猎人、墓园等随机性的对局，“完全一致”的结果来自替代种子，终局一致不代表中途每个细节都相同。
- 极端回放 02JYPPC02YUL 在所有种子下都会多打对方左塔约 1000 血，集中出现在剩余 0:44 强盗头子冲塔处，原因尚未查明（主客场已排除：对调真蓝 / 真红后整局无法执行）。
